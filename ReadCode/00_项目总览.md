# autoresearch 项目总览与设计理念

## 一、项目是什么？

**autoresearch** 是 Andrej Karpathy 提出的一个开创性项目，核心理念是：**让 AI Agent 自主进行 LLM 预训练实验**。

人类只需要在 `program.md` 中设置好实验规则，然后让 Agent 不断循环：

```
修改 train.py → git commit → 5分钟训练 → 读取 val_bpb → 保留/丢弃 → 循环
```

这相当于让一个 AI 研究员在你的 GPU 上 **24/7 不间断工作**。

## 二、核心设计哲学

### 2.1 "单文件修改"原则

| 文件 | 角色 | 是否可修改 |
|------|------|-----------|
| `prepare.py` | 数据下载、Tokenizer、DataLoader、评估函数 | ❌ 固定 |
| `train.py` | GPT 模型、优化器、训练循环、超参数 | ✅ Agent 可改 |
| `program.md` | Agent 的实验规则/指令 | ✅ 人类可改 |

**为什么这样划分？**

- **评估固定**：`evaluate_bpb` 不可改，Agent 无法"作弊"优化指标
- **数据固定**：每次实验用相同的数据，对比公平
- **修改范围可控**：只需关注一个文件，diff 审查简单
- **Agent 自由空间**：模型架构、优化器、超参数全部开放

### 2.2 固定时间预算（5 分钟）

```python
# prepare.py:31
TIME_BUDGET = 300  # 5分钟
```

**为什么用时间而不是步数？**

| 优势 | 说明 |
|-----|------|
| 公平比较 | 大模型/小模型在相同计算资源下对比 |
| 实际优化 | 优化"在我 GPU 上 5 分钟能得到的最好模型" |
| 鼓励高效 | Agent 自然倾向于选择计算高效的架构 |
| 快速筛选 | 5 分钟足以排除明显不好的想法 |

### 2.3 BPB（Bits Per Byte）指标

与词表大小无关的指标。计算方法：

```
BPB = Σ(loss_i × bytes_i) / (log(2) × Σ bytes_i)
```

其中 `bytes_i` 是每个 token 的 UTF-8 字节长度，预存在 `token_bytes.pt` 中。

**为什么重要？** 如果你把词表从 8192 改到 32768，per-token loss 会变，但 BPB 不变——不同词表大小的模型可直接比较。

## 三、技术栈

```
语言: Python 3.10+
框架: PyTorch (CUDA)
GPU: NVIDIA H100 (推荐)
核心依赖:
  - kernels (Flash Attention 3)
  - rustbpe + tiktoken (BPE tokenizer)
  - pyarrow (Parquet 数据)
编译: torch.compile (全图编译)
精度: bfloat16 (AMP autocast)
```

## 四、默认模型配置（DEPTH=8）

```
模型维度: 512 (depth × ASPECT_RATIO = 8 × 64)
注意力头数: 4 (512 // HEAD_DIM = 512 // 128)
层数: 8
序列长度: 2048
词表大小: ≈8192（实际由 tokenizer 决定）
注意力模式: SSSL (3层滑动窗口 + 1层全注意力)
参数数量: ~50M
优化器: Muon (矩阵) + AdamW (其他)
批大小: 524K tokens/step, 梯度累积
```

## 六、Agent 工作流程

### Setup（人类确认后执行）
1. 创建分支 `autoresearch/<tag>`
2. 验证数据和 tokenizer 存在于 `~/.cache/autoresearch/`
3. 初始化 `results.tsv`

### 实验循环（FOREVER）
```
1. 查看 git 状态
2. 用实验想法修改 train.py
3. git commit
4. uv run train.py > run.log 2>&1
5. grep "^val_bpb:" run.log → 提取指标
6. crash → 尝试修复或记录并跳过
7. val_bpb 下降 → 保留 commit（进展）
8. val_bpb 不变/上升 → git reset
```

### 结果记录（results.tsv）

## 七、项目哲学：从"手动研究"到"自主研究"

| 传统研究 | autoresearch |
|---------|-------------|
| 人类执行每一步实验 | AI 执行实验循环 |
| 人类的直觉驱动 | `program.md` 编码的规则驱动 |
| 每天做几次实验 | 每小时 ~12 次实验，每天 ~288 次 |
| 手动记录结果 | `results.tsv` 自动记录 |
| git 是版本控制 | git 是实验账本 |
| 人类是优化器 | 人类是元优化器（设规则） |

**这是一种新的研究范式**：人类提供研究方向和判断标准，AI 提供大规模的搜索能力。每次成功的修改都是一次"进化"。
